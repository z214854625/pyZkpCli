# ZooKeeper Web 客户端

用浏览器连接 ZooKeeper，按树形浏览、搜索和管理节点。后端使用 Python、Flask 和 Kazoo。

## 启动

### Web 版

Windows 上可以运行 `start.bat`，也可以用 Python 3.9 或更新版本手动启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

打开 `http://127.0.0.1:8765`。端口可通过 `app.py --port 8766` 修改。

### Windows EXE 版

双击 `dist\pyZkpCli.exe` 会启动本地服务，并用默认浏览器打开和 Web 版相同的界面。EXE 已包含 Python 和页面资源，可以单独运行。关闭控制台窗口或按 `Ctrl+C` 可停止服务。

EXE 默认自动选取空闲端口，可以与 Web 版同时运行。可以在命令行用 `.\dist\pyZkpCli.exe --port 8767` 指定端口，或加 `--no-browser` 手动打开控制台显示的地址。

在 Windows 上运行 `build_exe.bat` 可以从当前代码重新生成 `dist\pyZkpCli.exe`。打包需要 Python 3.9 或更新版本，脚本会在 `.venv` 中安装打包依赖。

## 节点管理

- 在「连接服务器」输入 `host:2181`、逗号分隔的集群地址，或带根路径的 `host:2181/app`。需要 Digest 认证时，展开认证表单填写用户名和密码。
- Web 和 EXE 共用 `%LOCALAPPDATA%\pyZkpCli\connection_history.txt` 保存最近 10 个成功连接的不同地址，每行一个，最新的排在首行。启动时会显示并预填最新地址，打开「最近连接」可以选择其他地址。历史文件仅保存服务器地址。
- 点击树中节点查看数据、版本、子节点数和修改时间。支持 UTF-8、GBK 和 Base64 视图。UTF-8 无法显示的 `.ini` 会尝试按 GBK 打开，编辑后按所选编码保存。
- 搜索范围为当前选中的节点及其子节点，未选中节点时从根节点开始。搜索按完整节点名或完整路径匹配，忽略大小写，命中后跳过该节点的下级分支。默认只搜索有子节点的节点。勾选「仅搜索叶节点」后只搜索叶节点，也可以留空关键词列出叶节点。搜索会自动跳过没有匹配的批次，继续搜索时沿用原先的起点。节点详情中的定位按钮会展开搜索结果所在的路径。
- 保存和删除按读取时的 ZooKeeper 数据版本校验。选中有子节点的节点，点击删除并确认「删除子树」，即可删除该节点及其下所有层级的节点。根节点不可删除，`/zookeeper` 系统节点及其子节点只读。较大的子树分批提交，失败时会显示已确认删除的数量。

## 导入目录

选中目标父节点并点击「导入目录」，选择本地目录，然后确认显示的导入路径。在 `/app` 下导入 `configs` 目录时，本地文件 `configs/server/app.ini` 对应 `/app/configs/server/app.ini`。当前节点与本地目录同名时，界面默认选其父节点，便于再次导入。

导入会创建缺失的节点，按原始字节更新同路径的文件节点，并保留已有目录节点的数据。文件目标已有子节点时会提示冲突。支持浏览器目录选择器时，空目录也会导入。

每次上传最多 4096 个节点和 8 MiB 请求数据。较大的目录会分批通过 ZooKeeper 事务写入。中途发生错误时，界面显示失败路径及先前已提交的数量。重新导入同一目录可继续，内容一致的文件会跳过。

Web 服务默认监听 `127.0.0.1`，面向本机单人使用。一个服务进程共享一个活动连接，ZooKeeper ACL 由服务器校验。Digest 连接新建的节点默认仅对创建者授权，匿名连接新建的节点使用 ZooKeeper 的开放 ACL。
